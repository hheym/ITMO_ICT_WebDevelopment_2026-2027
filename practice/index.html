    Практические работы 2.1–2.3

    Студент: Забродин Максим
    Группа: K3340

    Код практических работ находится в папке practice.

    Практика 2.1 — Первое приложение Django

    Создан проект django_project_zabrodin и приложение project_first_app. Приложение подключено через INSTALLED_APPS.

    Модель данных

    По схеме задания реализованы четыре модели:

    Модель Назначение Основные поля
    CarOwner Автовладелец Имя, фамилия, дата рождения
    Car Автомобиль Госномер, марка, модель, цвет
    Ownership История владения Владелец, автомобиль, начало и окончание владения
    DriverLicense Водительское удостоверение Владелец, номер, тип, дата выдачи

    Модель Ownership содержит внешние ключи на владельца и автомобиль. В базе хранятся их идентификаторы, а Django позволяет обращаться к связанным объектам.

    Созданы и применены миграции:

    python manage.py makemigrations
python manage.py migrate

    Все модели зарегистрированы в Django Admin. Через панель добавлены два владельца, четыре автомобиля и шесть записей владения — по три автомобиля у каждого владельца.

    Страница владельца

    Обработчик получает владельца по ID и передаёт его в HTML-шаблон:

    def owner_detail(request, owner_id):
    owner = get_object_or_404(CarOwner, pk=owner_id)
    return render(request, "owner.html", {"owner": owner})

    Адрес /owner/<id>/ подключён через urls.py приложения и главный urls.py проекта.

    Проверен вывод существующих владельцев. При запросе несуществующего ID возвращается ответ 404.

    Практика 2.2 — Связи, представления и формы

    Связь «многие ко многим»

    В модель автомобиля добавлено поле:

    owners = models.ManyToManyField(CarOwner, through="Ownership")

    Один владелец может быть связан с несколькими автомобилями, а автомобиль — с несколькими владельцами за свою историю. Промежуточная модель Ownership хранит даты владения.

    Представления

    Список владельцев реализован функцией owner_list. Для автомобилей использованы готовые классы Django:

    Представление Назначение
    CarListView Список автомобилей
    CarDetailView Информация об автомобиле по ID
    CarCreateView Создание автомобиля
    CarUpdateView Редактирование автомобиля
    CarDeleteView Удаление автомобиля с подтверждением

    Для каждого действия созданы маршруты и HTML-шаблоны.

    Формы

    Форма добавления владельца первоначально создана на основе ModelForm. Обработка GET и POST реализована функцией owner_create.

    Через форму добавлены новые владельцы. Через CreateView добавлены три автомобиля.

    Проверены просмотр, создание и редактирование записей. Удаление проверено на отдельном временном автомобиле. Удаление выполняется POST-запросом со страницы подтверждения.

    Практика 2.3 — Расширение пользователя

    Автовладелец преобразован в пользователя сайта: класс CarOwner наследуется от AbstractUser.

    Помимо стандартных полей пользователя добавлены:

    birth_date = models.DateTimeField(null=True, blank=True)
passport_number = models.CharField(max_length=10, blank=True)
home_address = models.TextField(blank=True)
nationality = models.CharField(max_length=100, blank=True)

    В настройках указана пользовательская модель:

    AUTH_USER_MODEL = "project_first_app.CarOwner"

    Перед изменением сохранена резервная копия проекта и выгружены данные. Для новой структуры создана отдельная база SQLite, после чего записи перенесены обратно с сохранением ID. Перенесённым владельцам назначены уникальные логины.

    Панель администратора

    Для CarOwner используется класс на основе UserAdmin. Дополнительные поля включены в разделы создания и редактирования пользователя через add_fieldsets и fieldsets.

    Создание пользователя

    Форма CarOwnerForm переведена на UserCreationForm. Она содержит логин, имя, фамилию, дату рождения, паспорт, адрес и национальность, а также поля пароля и его подтверждения.

    Форма проверяет пароли и сохраняет хеш пароля.

    Отображение пользователя

    На странице владельца выводятся имя, фамилия, ID, дата рождения, логин и новые атрибуты.

    Проверены создание тестового пользователя через сайт и отображение его данных.

    Результат

    Освоены модели и связи Django, миграции, панель администратора, функциональные и классовые представления, HTML-шаблоны, формы и расширение модели пользователя.

    В практиках используется SQLite. Основная лабораторная работа реализована отдельно в папке labwork и использует PostgreSQL.
